# Agents Date

Every person is represented by an agent. The agent reads exactly two public profiles — a
LinkedIn profile and a public Instagram — and works out that person's needs, hobbies and
interests, citing the source line for every claim. Then the agents date each other, and
every person gets a ranked shortlist of who fits them best.

Try it: **[the live demo](/)** at `/demo` (pre-built, 26 people, nothing to type).

---

## What this actually does, and what it does not

This README leads with the limits, because they were measured, not assumed.

| Claim | Status |
| --- | --- |
| Pipeline runs end to end | Yes — verified with 82 unit tests and an integrity audit on real data |
| Every claim cites a source line | Yes — 321/321 transcript citations resolve; `npm run audit` proves it |
| Ranking is per-person, not one global list | Yes — 2.5% symmetric ties, and the rest are genuinely similar people |
| Reads LinkedIn automatically | **No.** LinkedIn returns HTTP 999 (bot-block) to anonymous requests |
| Reads Instagram automatically | **No.** Instagram serves a JavaScript-only page; its JSON API returns 401 |
| Sends messages to anyone | **No.** Conversations are generated by software, never delivered |
| The demo uses real people's profiles | **No.** 26 synthetic personas — see below |

### Why the demo is synthetic

While building this, both platforms were queried directly:

```
LinkedIn  -> HTTP 999   (their documented bot-block response, every user agent tried)
Instagram -> HTTP 200 with a client-rendered shell containing no profile text
             /api/v1/users/web_profile_info/ -> HTTP 401 without auth
```

So a shared link alone cannot be read by a third party without paid credentials. Rather
than fabricate scraped-looking data, this repo does two honest things:

1. **The consented-text path.** A person pastes the profile text their own profile
   already shows. The profile record still points at the real URL, and every trait is
   still cited to a line. This needs no credentials and works today.
2. **The Apify path.** Set `APIFY_TOKEN` and the official
   [`apify/instagram-profile-scraper`](https://apify.com/apify/instagram-profile-scraper)
   Actor reads real public Instagram profiles automatically. Same code path, same
   analysis, real data.

The demo run ships 26 synthetic personas so the analysis, dating and ranking can be
judged without a credential. The personas run through the **identical** pipeline — there
is no separate demo code path. Point the app at real links and it reads real profiles.

### LinkedIn is deliberately not automated

LinkedIn's [User Agreement §8.2](https://www.linkedin.com/legal/user-agreement) prohibits
using automated means to scrape or copy profile data without the content owner's consent.
An Apify adapter for LinkedIn exists in `src/ingest/apify.ts` but is **disabled by default**
and cannot be enabled without documented permission. Please do not turn it on for
third-party profiles. The compliant alternative is the person consenting to their own
data being read, which is what the pasted-text path is.

## Tech stack

**Scraping Instagram and LinkedIn — what is actually used**

| Layer | Choice | Why |
| --- | --- | --- |
| App | **Next.js 15.5.26** (App Router) + **React 19** + **TypeScript** (strict, `noUncheckedIndexedAccess`) | One deployable, server routes for the API, RSC for the demo |
| Instagram capture | **Apify** — official Actor `apify/instagram-profile-scraper`, REST API v2, server-side only | Officially built by Apify, pay-per-result, no browser to maintain |
| Apify call shape | `POST /v2/acts/{actor}/runs?waitForFinish=60&maxTotalChargeUsd=…` then `GET /v2/datasets/{id}/items` | The charge cap is a **query parameter**, never part of the input body |
| LinkedIn capture | **Disabled by default.** When permitted, a community Actor via the same REST call | LinkedIn ToS §8.2; consent required |
| Fallback capture | Direct `fetch` of the public page + consented pasted text | Zero credentials, works today |
| Analysis | Deterministic trait extraction over a canonical taxonomy with word-boundary matching | Auditable and citation-preserving; no LLM hallucination in the claim path |
| Matching | Weighted directed scoring, 5 components | Every component shows its own explanation |
| Dating | Structured multi-turn generation with evidence on each turn | Grounded, reproducible, no invented biography |
| Storage | Atomic filesystem store behind a `RunStore` interface | No credentials needed; swap for a hosted DB without touching callers |
| Tests | **Vitest**, 82 tests | Includes regression tests for every fixed defect |
| Integrity check | `npm run audit` | Verifies citations on a real run file, not mocks |

### Environment variables

| Variable | Required | Effect |
| --- | --- | --- |
| `APIFY_TOKEN` | no | Enables automatic Instagram capture |
| `APIFY_MAX_CHARGE_USD` | no | Per-capture cap. Parsed defensively and clamped to ≤ $2 — an empty or unparseable value falls back to $0.50 rather than silently disabling the cap |
| `AGENTS_DATE_DATA_DIR` | no | Where runs are stored. Defaults to `.data/runs` |

## Running it

```bash
npm install
npm run seed        # build the 26-person demo run into data/demo.json
npm run dev         # http://localhost:3000
```

```bash
npm run typecheck   # tsc --noEmit
npm test            # 82 unit tests
npm run audit       # evidence integrity over a real run file
npm run build       # production build
```

To read real Instagram profiles, put a token in `.env.local`:

```
APIFY_TOKEN=your_token_here
```

## How it works

```
LinkedIn URL  ┐
              ├─→ capture ─→ analysis ─→ ranking ─→ dates
Instagram URL ┘     (2 sources)   (cited)   (directed)  (grounded)
```

**1. Validate.** Company pages, school pages, Instagram posts and reels are rejected with
a specific message before any network work happens. Duplicate profiles are caught too.

**2. Capture.** Apify if a token exists, else an anonymous read, else consented pasted
text. A source that cannot be read is recorded as a gap — it is never filled with a
plausible-looking guess. HTTP-200 placeholder pages ("this page isn't available", login
walls) are detected and treated as failures rather than captures.

**3. Analyse.** Each line is classified, then matched against a shared taxonomy with
word-boundary matching. A trait seen on both sources scores higher. Repetition alone does
not raise confidence. The profile page shows what the sources do **not** say: age,
orientation, relationship status and availability are never inferred.

**4. Rank.** Five weighted components, each explained on every match card:

| Component | Weight | Directional? |
| --- | --- | --- |
| Shared ground | 30% | symmetric by nature |
| Meets your needs | 26% | yes — A's needs, B's profile |
| Adds something new | 18% | yes — what B brings that A lacks, minus redundancy |
| Evidence quality | 16% | yes — weighted 2:1 toward the candidate |
| Values | 10% | yes — A's values, B's overlap |

A's ranking of B is computed independently from B's ranking of A.

**5. Date.** Two agents alternate through openings, shared ground, a curiosity about a
trait only one side has, a real tension, and reflections. Every turn carries the evidence
that prompted it, tagged with whose profile it came from.

## Ethics

This tool profiles real people. That is inherently sensitive, so the design is
constrained around it:

- Only public profile content is read, and only from two sources per person.
- Every claim is cited, so a claim about someone can always be audited against the line
  that produced it.
- The app refuses to infer age, orientation, relationship status or availability.
- It reports its own gaps rather than filling them.
- Conversations are labelled as software-generated, and are never sent to anyone.
- LinkedIn automation is off by default because the platform's terms require consent.

Do not use this to profile someone without their knowledge. If you would like a person
removed, open an issue with their profile URL.
